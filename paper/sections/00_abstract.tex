\begin{abstract}
Every input to a language model is first segmented into tokens by a subword
vocabulary; that vocabulary is trained once and reused across domains, yet the
corpus it is trained on is rarely matched to the text it must encode. We ask how
much that mismatch costs when encoding specialized technical documentation. In a
controlled, CPU-only study, we train byte-level BPE tokenizers that are identical
in algorithm, settings, vocabulary size, and training-byte budget and differ only
in their training corpus---General-English, Azure documentation, or a 50/50
mix---and measure how many tokens each needs to encode unseen documents. Training
corpus alone produces large, consistent differences. On a set of Azure services
withheld entirely from training, the Azure tokenizer encodes text with
\reduc{36.68} fewer tokens than the byte-matched general tokenizer (95\% CI
$[35.77\%, 37.62\%]$)---and does so on every one of 964 held-out documents. The
gain is directional: the same tokenizer spends \reduc{34.75} more tokens on
ordinary English. A single 50/50 mixed tokenizer largely resolves this tension,
keeping \reduc{93.3} of the in-domain gain while costing only \reduc{4.39} more
tokens on general English. The advantage is stable across 8K--32K vocabularies,
persists on prose-dominant pages, and transfers to other Microsoft and external
(Kubernetes) documentation never seen in training. We study tokenizer
\emph{compression} only---making no claims about model quality, inference latency,
GPU throughput, or cost---and release all code, pinned data manifests,
per-document measurements, and a machine-verified registry that reconciles every
reported number to its source.
\end{abstract}
